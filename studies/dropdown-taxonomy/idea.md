# 下拉框

往下展开只是外观。真正要先定的是**提交模型**。

## 问题

「做个下拉」描述的是外观：一块面板往下打开。真正会坏掉的是**提交规则**：

- 选完该不该关？
- 一次交一个值，还是交一组、一条路径、一次动作、一段日期？
- 分组标题是不是层级？
- 按钮主体能不能直接执行？

用同一个 Select 去扛这些差异，用户会在错误的时机丢掉选择、点不到默认操作，或把分类当成上下级。

## 规则

先按「什么被提交、面板何时关闭」选模型，再谈外观。

| 模型 | 提交的是什么 | 面板何时关 |
| --- | --- | --- |
| Select | 扁平固定列表里的**一个**值 | 点中即关 |
| Multi-select | 一个集合（标签）；可设上限 | **不关**；标签上单独删，或一键清空 |
| Grouped Select | 仍然是一个值；分组只是标签 | 点中即关 |
| Cascader | 必须到叶子的**路径**；父级只展开 | 点到叶子才提交并关闭；触发器显示完整路径 |
| Split Button | 主体立刻执行默认动作；箭头才是低频动作 | 只有箭头打开菜单 |
| Mega Menu | 不是表单值，是多列导航 | 点链接或点其它导航项 |
| Date range | 先入住再离店；过去不可选 | 两端齐了才是一段；晚数 = 日历日差 |

最容易混的一对：**Grouped 是分类，Cascader 才是上下级。** 分组标题不能点成路径；父级行政区不能当成最终值。

说清楚一条交互，用三件事：

1. **名称** — 不要说「下拉框」
2. **场景** — 一次选什么
3. **规则** — 单选 / 多选 / 必须到叶子 / 过去禁选 / 主体必须能直接点

## 和「再包一层 Popover」的差别

| | 一律当 Select | 按提交模型分 |
| --- | --- | --- |
| 技能标签 | 选一个就关，第二项进不去 | 开着，标签可单独摘掉 |
| 省市区 | 把「浙江省」当成最终值 | 父级只展开，叶子才提交路径 |
| 发布 | 默认动作藏进菜单 | 主体直接发布，箭头才是定时 / 草稿 |
| 酒店日期 | 一个 input type=date | 两端、禁过去、显示晚数 |

## 机器

这里的 Cascader 是点选列，Mega Menu 是点击展开。它们都不跟手。

状态机在无 DOM 的模块里：`toggleMulti`、`pickCascade`、`pickRangeDay`。

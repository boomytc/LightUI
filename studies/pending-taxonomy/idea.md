# 等待

内容还没到，屏幕上该留什么？先定是**骨架占着布局**，还是**空状态给人下一步**。

## 问题

「做个 loading」描述的是外观：转圈、灰块、或一块白板。真正会坏掉的是**占位和内容对不上**：

- 列表还在路上，中间丢一个转圈，到达后整页重排
- 扫光靠闪透明度，像在报警，不像在铺位子
- 到达时硬切，卡片突然弹出来
- 列表是空的，却写「暂无数据」，或只剩一块白板
- 空状态做成一条 toast，瞄一眼就没了，没有下一步
- 减少动效时扫光还在跑

用同一种转圈或「暂无数据」去扛这些差异，不是布局跳，就是人不知道该做什么。

## 规则

先问内容是**还在路上**，还是**已经到了、只是没有**。再选叶子。

| 叶子 | 何时 | 机器 |
| --- | --- | --- |
| 骨架屏 | 结构已知，内容还在路上 | `reservesLayout`；占位块宽高贴近最终布局；扫光用 **背景位置循环**，不要闪透明度；到达后短交叉淡入；**不要转圈代替骨架**；`prefers-reduced-motion` 停扫光，留灰块 |
| 空状态 | 已经到了，这一份是空的 | `hasAction`；图标 + 一句人话标题 + 一句引导 + **一个主按钮**；禁止「暂无数据」和白板 |

两片叶子都 **`allowsSpinner` 为假**。转圈是不确定进度，不是等待占位。

最容易混的两对：

- **骨架不是转圈进度。** 骨架占的是布局位子，到达后换成真内容。转圈说的是工作正在发生、进度还不能算。
- **空状态不是一条提示。** 提示报一条已经发生的消息。空状态占着这块区域，告诉人为什么空、下一步点哪里。

说清楚一次等待，用三件事：

1. **名称** — 不要说「做个 loading」，说骨架屏或空状态
2. **场景** — 内容还在路上，还是已经到了、这一份是空的
3. **规则** — 占位贴布局、背景扫光、短交叉淡入；或人话标题加一个主按钮

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一律转圈 / 暂无数据」的差别

| | 一律转圈或白板 | 按占位分 |
| --- | --- | --- |
| 卡片列表加载 | 中间一个圈，到达后重排 | 三张假卡贴真卡，扫光后淡入 |
| 减少动效 | 扫光还在闪 | 停扫光，留下灰块 |
| 还没有任何简报 | 「暂无数据」，或一块白 | 「还没有简报」+ 引导 + 新建 |
| 工作还在算 | 骨架当进度 | 进度是另一问；这里不转圈 |

## 机器

判断在无 DOM 的模块里：`reservesLayout(kind)`（骨架为真）、`hasAction(kind)`（空状态为真）、`allowsSpinner(kind)`（两片都为假）、`occupancy(kind, state)`（skeleton / content / empty）。扫光是 `background-position`，不是 `opacity` 闪烁。

# 控件

「做个输入框」只说了能填。真正要先定的是**这一格是自己填，还是从已有答案里选**。

## 问题

「做个输入框」描述的是外观：一块能敲字的格子。真正会坏掉的是**填和选用了同一种机器**：

- 需求描述被塞进一行，写不下只能挤
- 邮箱被做成多行，短内容漂在大框里
- 三种配送藏进下拉，价格和时效比不了
- 五个城市却先强迫打字搜索
- 两百个同事摊成一张长列表，找不到人
- 兴趣标签做成圆点，第二项会挤掉第一项
- 「同意条款」做成单选组，看起来像互斥档位

用同一个文本框去扛这些差异，用户会填错栏、比不了、搜不到，或把多选当成单选。

## 规则

先问用户要干什么，再落到一种机器。

| 先问 | 再问 | 机器 |
| --- | --- | --- |
| 自己填 | 一行就够 | 单行文本 |
| 自己填 | 要写一段 | 多行文本 |
| 从答案里选 | 可以同时多个 | 复选 |
| 从答案里选，只能一个 | 很少、要并排比较 | 单选组 |
| 从答案里选，只能一个 | 固定 5–15 项、扫一眼 | 下拉 Select |
| 从答案里选，只能一个 | 很多、要先搜再选 | Combobox |

最容易混的三对：

- **单行不是多行。** 姓名、邮箱是一行。简介、需求是一段，占满一栏，带字数。
- **可见单选不是下拉。** 2–5 项要同时看见才能比较。选项一多再收到面板里。
- **可搜索不是固定列表。** 上百项要先打字。五个城市不该先强迫搜索。

说清楚一格，用三件事：

1. **名称** — 不要说「输入框」
2. **场景** — 填短内容、写一段、比较三档，还是从两百人里找
3. **规则** — 自己填 / 只能一个 / 要能搜 / 可以同时多个

这三件事收成一句，就是卡片上的「说清楚」。复制出去就能当说明，不必另开一套说法。

单个「同意条款」也是复选：它是一个布尔，不是互斥档位。

## 和「一律做成输入框」的差别

| | 一律输入框 | 按填 / 选分 |
| --- | --- | --- |
| 注册邮箱 | 多行或带搜索的怪框 | 一行，失焦才说空 |
| 需求描述 | 挤在一行里 | 多行，右下字数 |
| 三种配送 | 藏进下拉，比不了时效 | 全部可见，只能一个 |
| 所在城市 | 先弹出搜索 | 打开短列表，点中即关 |
| 找同事 | 把两百人摊开 | 输入即筛，再点一个 |
| 兴趣标签 | 点一个另一个没了 | 可叠，到上限其余禁用 |

## 机器

判断树在无 DOM 的模块里：`nextStep`、`chooseControl`、`answersFor`。筛选是 `filterMembers`，多选上限是 `toggleCapped`。

Select 叶子只示范「固定短列表、点中即关」。面板还可以交一组、一条路径、一次动作——那是下一问，不在这一则展开。Combobox 也往下开，但先问的是怎么找到选项，不是提交什么。

# 分组

「做个模块」只说了有内容。真正要先定的是**这几块内容之间的语义关系，以及用哪种手段隔断**。

## 问题

AI 生成界面和初学者设计最常见的审美惯性，就是**「万物皆卡片」**：
- 标题套一张卡、数据套一张卡、介绍再套一张卡
- 注册表单里的 6 个输入框，每个单独做成带边框、圆角、阴影的白底方块
- 动态流里的每一条操作日志，都包上一层厚重的卡片外壳
- 介绍长文的「为什么 / 怎么做 / 成果」被切成三张便利贴
- 并排比较的三款套餐，被做成互相孤立的定价卡

这种“安全捷径”把原本连续、有层级的叙述，暴力切碎成**「便利贴墙」**。用户的视线被迫在无数个圆角外框和阴影之间跳跃，阅读流被打断，页面杂乱且千篇一律。

## 规则

**卡片只该装真正独立、可被单独拿起或操作的对象（如看板里可拖拽的任务卡、收藏夹里的独立项目）。**
其余内容，必须先判断语义关系，再选择对应的隔断技法：

| 技法 | 关系类型 | 场景 | 核心规则与 CSS 手段 |
| --- | --- | --- | --- |
| **00 默认卡片** | 独立实体 | 任务卡、独立项目 | `border-radius: 16px` + `box-shadow`。作为反面教材与对照基准，非独立实体严禁滥用 |
| **01 留白分区** | 上下承接 | 介绍页、详情页、长文 | 靠垂直节奏（`margin-top: 2.5rem`）+ 1px 细分割线（`border-top`）自然推进，**禁止 background / radius / shadow** |
| **02 表单分组** | 同一填写任务 | 注册流程、资料设置 | 按任务划分子区（如基本信息 / 工作信息）；字段采用网格与底部边线（`border-bottom`），字段本身不套卡 |
| **03 单列列表** | 连续发生 | 消息、记录、动态流 | 单列纵向排开，提供单一清晰扫视路径；序号与时间右对齐，行悬浮轻微变色，禁止每个事件套卡 |
| **04 通栏色块** | 整行同主题 | 功能段落、专题区、行动区 | 用整行背景色带（`bg-band`）划定区域边界，行内多列项目保持纯扁平无框 |
| **05 竖向分割线** | 并列比较 | 套餐对比、产品版本 | 共享同一张底板与对齐网格，仅在列与列之间加细竖线（`border-inline-start`），保持横向对比的整表感 |

## 和「万物皆卡片」的差别

| 场景 | 一律套卡片（便利贴墙） | 按语义关系分组 |
| --- | --- | --- |
| **产品叙述（Why / How / Result）** | 三张并列小卡片，像三项孤立特性 | 留白分区，细线分隔，一条阅读轴顺畅读完 |
| **用户注册表单（6 个输入项）** | 六张带阴影卡片网格，焦点分散 | 表单按任务分两组（基本/工作），字段扁平排列 |
| **团队动态流（10 条记录）** | 十张大卡片，眼睛在格子间反复跳跃 | 单列紧凑列表，视线顺流直下，支持快速筛选 |
| **功能专题矩阵** | 九张方块卡片塞满屏幕 | 三条同主题色带，区域层次清晰明确 |
| **套餐价格对比** | 三张割裂卡片，难以横向扫视参数 | 共享底板 + 细竖线分割，对齐感强，差异一目了然 |

## 约束 AI 的 Prompt 准则

```text
设计页面时先判断内容关系，再选择分组方式。禁止把每个模块默认装进带圆角、边框、阴影的卡片。

规则：
1. 上下承接的阅读内容（介绍、详情、长文）：用留白和细分割线建立节奏，不要每段加框。
2. 同一填写任务（注册、资料、设置）：按任务分组表单字段（如基本信息 / 工作信息），字段本身不要各自套卡片。
3. 连续发生的信息（消息、记录、动态）：用单列列表，让视线沿一条路径扫过。
4. 整行同主题的功能区：用通栏色块建立区域，不要给每一项单独套卡片。
5. 需要并列比较的内容（套餐、版本、服务）：用竖向分割线分栏，保留整体，不要切成三张独立卡。

卡片只用于真正独立、可被单独拿起操作的对象。关系才是分组答案。
```

## 机器

判定与校验纯函数位于 `src/lib/machines.ts`：
- `PATTERNS`：5+1 技法元数据与 CSS / Prompt 规范
- `isPatternId` / `nextPattern` / `prevPattern`：键盘驱动导航与模态状态机
- `gradeQuizAnswer`：场景自测判定与解析

# 空白

看起来都是一块空，真正要先定的是**为什么空，以及这一次该让人做什么**。

## 问题

「做个空状态」描述的是外观：插画、一句「暂无数据」、一个按钮。真正会坏掉的是**空因不同、却用同一种催促**：

- 新账号还没有任何客户，却写「暂无数据」，人不知道第一步点哪里；概览还画一排 0
- 搜了一个近音词没有结果，空井里再放「添加客户」，人以为库是空的
- 叠了城市、本周、成交三个条件没有匹配，页面看起来像一条记录都没有
- 刷新失败，把原来的列表换成白板，工作中断；第一次请求失败也被说成「还没有内容」
- 今天的待办做完了，还在催「去添加」

用「提示 + 一个按钮」去扛这些差异，不是把「没匹配」说成「没数据」，就是在不该催的时候催。

## 规则

先问这一次为什么空，再落到一种引导。等待占位（骨架 / 空 / 遮罩）是另一问。

| 叶子 | 何时 | 机器 |
| --- | --- | --- |
| 首次使用 | 库里还没有任何记录 | `emptyAction` 为 `create`；人话标题 + 写清「添加第一位客户」的主按钮 + 导入入口；空概览不要一排 0 |
| 搜索无果 | 记录在，关键词没命中 | `revise-query`；保留搜索框和刚才的词；修改建议放在框旁；**空井里不要再放创建主按钮**（顶栏添加可以留，说明库还在） |
| 筛选无果 | 记录在，条件过严 | `loosen-filter`；条件留在页面上，允许逐个移除；少一个条件，结果可能就回来 |
| 加载失败 | 请求失败，不是空 | `retry`；`keepsExistingList`；顶部轻提示 + 文字重试；**不能当成没有数据** |
| 全部完成 | 待办清零，历史还在 | `celebrate`；明确完成反馈；**不要再催操作**；历史留在原导航 |

最容易混的几对：

- **为什么空不是屏幕上该留什么。** 骨架占布局、空状态给人下一步、整页遮罩盖未知的壳，是等待占位。这一则问的是已经空了之后，空因是什么、该催创建还是改条件。
- **空占位不是一律一个主按钮。** 给人下一步，只对还没开始成立。搜索改词、筛选改条件、失败重试、完成庆祝，都不是再放一个创建。顶栏添加说明库还在，不是空井里的主按钮。
- **没匹配不是没数据。** 搜索改关键词，筛选改条件。主按钮只给还没有任何记录的那一次。
- **加载失败不是空，也不是进度。** 原列表还在，旁边给重试。第一次请求失败也是失败，不要改口成「还没有客户」。转圈进度是另一问。
- **全部完成不是首次使用。** 清零是好消息。没有记录才是还没开始。

说清楚一次空白，用三件事：

1. **名称** — 不要说「做个空状态」，说首次使用、搜索无果、筛选无果、加载失败或全部完成
2. **场景** — 还没有内容、关键词没命中、条件过严、请求失败、还是待办清零
3. **规则** — 创建给入口 / 搜索改关键词 / 筛选改条件 / 失败可重试并保留列表 / 完成给反馈

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一律暂无数据 + 按钮」的差别

| | 一律提示 + 按钮 | 按空因分 |
| --- | --- | --- |
| 新账号 | 「暂无数据」，或概览一排 0 | 「还没有客户」+ 添加第一位客户 + 导入 |
| 搜近音词没命中 | 空井里再放一个添加按钮 | 框里还是刚才的词，框旁写改关键词 |
| 三个筛选叠在一起 | 看起来像一条都没有 | 标签留着，点 × 少一个条件 |
| 刷新失败 | 白板，或当成空 | 原列表还在，顶部「重试」 |
| 今日待办做完 | 再催去添加 | 「今天的跟进已全部完成」，历史还在 |

## 机器

判断在无 DOM 的模块里：`emptyCause`（first-use / search / filter / error / done / populated）、`emptyAction`、`showsPrimaryCta`（仅首次使用为真）、`keepsExistingList`（失败与有数据为真）。搜索优先于筛选。失败优先于空——0 条时失败仍是失败，不是首次使用。完成要求历史还在。

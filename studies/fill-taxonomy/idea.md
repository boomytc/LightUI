# 填写

「做个表单」只说了有格子。真正要先定的是**填写前、填写中、提交后，这一栏该交代什么**。

## 问题

「做个表单」描述的是外观：一列输入框，排整齐。真正会坏掉的是**三个时刻用同一种沉默**：

- 只靠占位符，输入几个字后就不知道这一格填什么
- 必填到提交才骂人，选填看起来也像非填不可
- 手机号没有格式示例，错了才在页顶甩一句「请检查」
- 活动时间、地点、名额本是已知事实，却让人再填一遍
- 错误写在页顶，对不上是哪一栏，也不说该怎么改
- 提交只弹「成功」，不知道发生了什么，也没有下一步

用「把字段排整齐」去扛这些差异，不是填到一半不知道自己在填什么，就是提交后还要猜结果。

## 规则

先问这一栏在哪个时刻开口，再落到一种职责。格子是填还是选，错误何时开口，都是另一问。

| 时刻 | 开口 | 这一课怎么试 |
| --- | --- | --- |
| 填写前 | 标签常在、必填选填先标、格式提前说、按任务分组 | 输入几个字看占位符是否消失；打开必填标记；对照叠了两行和一行替换；对照一串排到底和分组 |
| 填写中 | 占位给格式、真正的默认值预选；错了写在这一栏下，说清哪里错和该怎么改 | 给出格式占位和预选席位；对照同一截短号码：页顶一句失败，对不上栏；栏下还差几位，带着改法 |
| 提交后 | 写清发生了什么，并给出下一步 | 提交后不要只剩「成功」两个字 |

最容易混的三对：

- **交代什么不是填还是选。** 一行或一段、可见单选或短列表，是格子的机型。这一则问的是三个时刻各自说什么。
- **当场能改不是错误何时开口。** 文案写在这一栏下，同时说哪里错和该怎么改。失焦、行内、提交，是另一问。
- **提交成功不是一条 toast。** 结果页写清发生了什么和下一步。通知条报一声就走，对不上这一张表。

说清楚一种填写职责，用三件事：

1. **名称** — 不要说「做个表单」
2. **场景** — 填写前看标签、必填、格式、分组；填写中给占位和当场能改；提交后给结果
3. **规则** — 标签常在 / 必填先标 / 说明与错误不叠行 / 已知事实只读 / 错在栏下且能改 / 成功带下一步

这三件事收成一句，就是卡片上的「说清楚」。

占位符绝不当标签。颜色不能是必填的唯一信号。有错误时用错误文案替换辅助说明，不要两行叠在一起。

## 和「一律排整齐」的差别

| | 一律排整齐 | 按三个时刻交代 |
| --- | --- | --- |
| 输入几个字 | 占位符没了，不知道填什么 | 标签还在框的上方 |
| 选填的公司 | 看起来也像必填 | 写明「选填」 |
| 手机号 | 没有示例，页顶一句失败 | 框下给格式；少一位就说还差几位 |
| 活动时间地点 | 再填一遍已知事实 | 只读展示，按任务分组 |
| 提交之后 | 只弹「成功」 | 确认发到哪，并给出下一步 |

## 机器

职责在无 DOM 的模块里：`phaseOf`、`identityLost`、`fieldMark`、`shownCopy`、`hintKind`、`sectionsFor`、`isReadout`、`phoneRepair`、`repairPlacement`、`outcomeComplete`。

- 填写前：标签是否还在、必填选填是否标出、说明与错误是否叠行、已知事实是否变成只读
- 填写中：占位是格式还是空；错写在栏下还是页顶，文案有没有改法。何时开口是另一问
- 提交后：`what` 与 `next` 都在才算交代完，缺一个就是只报「成功」

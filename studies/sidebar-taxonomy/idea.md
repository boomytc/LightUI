# 给侧栏起对名字

贴在左边只是外观。真正要先定的是**空间模型**。

## 问题

「做个侧边栏」描述的是位置：一块导航靠左。真正会坏掉的是**空间怎么让给主内容**：

- 默认占不占位？
- 贴边还是离边？
- 展开是变宽，还是盖上来？
- 选项是目录树，还是一条选择器？
- 父级是归类，还是页面本身？

用同一个「固定贴左边栏」去扛这些差异，主区会被永远挤窄，或在小屏上找不到入口。

## 规则

先按「默认占不占位、展开改的是宽度还是图层」选模型，再谈皮肤。

| 模型 | 默认占位 | 展开时发生什么 |
| --- | --- | --- |
| 悬浮岛 | 占位，但不贴边 | 仍是一张卡；四周留白建立层级 |
| 弧形滚轮 | 占位 | 选项沿圆弧滚动，到基准线才高亮；它是选择器，不是树 |
| 多级 | 占位 | 父级只归类，点开后展开缩进的子项 |
| 可折叠 | 占位，但宽度可变 | 展开有文字；收起只留图标，主区跟着变宽 |
| 隐藏式 | **不占位** | 从画布外滑入，盖住内容；Esc / 遮罩关闭 |

最容易混的两对：

- **可折叠不是隐藏式。** 折叠后仍占一条图标栏；隐藏式默认宽度为零。
- **多级不是滚轮。** 多级是树：父级归类、子级才是页。滚轮是一条有序选择器，到达基准线才提交当前项。

说清楚一条侧栏，用三件事：

1. **名称** — 不要说「侧边栏」
2. **场景** — 工作台、作品集、后台、分析、长文目录
3. **规则** — 贴边 / 离边、默认占位、变宽还是盖上来、父级能不能当页

## 和「再包一层固定 aside」的差别

| | 一律贴左边栏 | 按空间模型分 |
| --- | --- | --- |
| 作品集浏览 | 五项全亮、没有当前项 | 滚轮：只有基准线那一项是选中 |
| 分析看板 | 永远占 240px | 折叠后主区吃回宽度 |
| 长文目录 | 一直挤着正文 | 隐藏式默认让出整栏，需要时再滑入 |
| 复杂后台 | 扁平一列点不完 | 父级归类，子级缩进 |

## 和另外三则 study 的关系

[给下拉起对名字](/s/dropdown-taxonomy) 处理的是往下展开的面板提交什么。[菜单意图预测](/s/intent-cascade) 处理的是 hover 多级已经定了之后，斜向穿越不该误切换。[给导航起对名字](/s/nav-taxonomy) 处理的是站点主导航住在哪、怎么开。本则更早一步——这块靠左的东西到底占不占位、怎么让路。

这里的多级是点击手风琴。若改成 hover 跟手，才需要那则 study 的走廊。

状态机在无 DOM 的模块里：`stepIndex`、`wheelVisual`、`toggleBranch`、`occupyPx`。

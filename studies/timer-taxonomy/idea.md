# 计时

这一段时间是正数累计，还是倒数专注？先定**会话的方向**，再画数字。

## 问题

「做个计时器」描述的是外观：一个在走的数字。真正会坏掉的是**方向搞反**：

- 正数累计被画成有上限的假番茄，走到 25 就假装完成
- 倒数专注被做成越走越大，人不知道还剩多久
- 专注过点还继续变成负数
- 进行中切到别的页面，顶栏把这段会话藏起来，人以为停了
- 用转圈代替数字，进度还不能算却假装在计时
- 到点弹一条 toast，计时器自己不停
- 把今日目标百分比套在这一段会话上

用同一种「走着的数字」去扛这些差异，不是让人看错已经过了多久，就是让人以为马上结束。

## 规则

先问这一段会话是**从 0 往上走**，还是**从 N 分钟往下走**。再选叶子。

| 叶子 | 何时 | 机器 |
| --- | --- | --- |
| 累计 | 没有会话上限，数字是已经过了多久 | `displaySeconds` = `liveSeconds`；暂停保留 accumulated；结束清零；`sessionProgress` 为 null |
| 专注 | 从 N 分钟往下走，数字是还剩多久 | `displaySeconds` = remaining；elapsed 到 cap 必须停在 0（pause），不要变负数；进度是这一段 elapsed/cap，不是今日目标 |

两片叶子共用：

`liveSeconds(t, now) = accumulated + (running ? now − startedAt : 0)`

`now` 和 `startedAt` 用 unix 秒。

进行中切到别的假页面，**顶栏仍要露出这段会话**（一颗时间 chip）。这是规则，不是第三叶。

不要用不确定进度转圈代替数字。

产品里常用 25 分钟；playground 用 1 分钟，方便看到结束。舞台锁住 elapsed，不跟墙上的钟走。

最容易混的几对：

- **计时不是进度条的「能不能算」。** 进度问工作有没有百分比；计时问这一段会话的方向。
- **到点不是一条 toast。** 专注到 0 时计时器自己停在完成态。
- **累计不是专注。** 把倒数做成越走越大，或把累计做成有上限的假番茄，都会坏。

说清楚一次计时，用三件事：

1. **名称** — 不要说「做个计时器」，说累计或专注
2. **场景** — 这一段要往上加，还是从 N 分钟往下走
3. **规则** — live 公式；暂停保留；专注停在 0；进行中顶栏仍露出

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一律一个走着的数字」的差别

| | 一律正数或假番茄 | 先问方向 |
| --- | --- | --- |
| 自由学习 | 25 分钟上限，到点假装完成 | 从 0 往上，没有会话上限 |
| 专注一段 | 数字越走越大 | 从 N 往下，显示还剩多久 |
| 到点 | 弹 toast，数字继续跑成负数 | 停在 0，完成态 |
| 切到计划 | 顶栏把会话藏起来 | 一颗时间 chip 仍露出 |
| 工作百分比 | 拿今日目标当这一段的环 | 累计没有会话百分比；专注环是 elapsed/cap |

## 机器

判断在无 DOM 的模块里：`liveSeconds`、`focusCapSeconds`、`remainingSeconds`、`displaySeconds`、`sessionProgress`、`shouldStopFocus`、`pause` / `start` / `end`、`formatDuration`。舞台用 `stageSnapshot(kind, state)` 锁住 `{ elapsed, running }`，不跟墙上的钟走。

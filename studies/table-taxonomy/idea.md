# 记录表

记录表先问**找、看、改落在哪一层**。筛在这一列的表头，条件留在表格上方；表头钉在表自己的滚动区里，名称列不能藏；一行只露出查看，其余收进这一行；有勾选，批量条才换掉搜索。

## 问题

「做一个表格」描述的是字段。真正会坏掉的是找、看、改没有自己的层：

- 筛选项做在表外面的一张表单里，看不出筛的是哪一列
- 勾一个标签，表立刻变，草稿和应用分不开
- 点金额把人筛没了，或者方向看不出来，条数还变了
- 整页滚动，表头走了；横着滑，也不知道是哪一位客户
- 每个角色都看见全部字段，名称还能被关掉
- 查看、编辑、复制、删除四颗按钮排在每一行
- 一个人都没选，批量改状态已经占着工具条
- 全选把被筛掉的行也勾上
- 筛了三项，上面不写，只能再打开表头才知道；清空时把名称搜索一起清掉

## 规则

先问这一下是在**找、看，还是改**，再谈皮肤。

| 叶子 | 落点 | 规则 |
| --- | --- | --- |
| 表头筛选 | 找 | 从这一列的表头多选。列内匹配任意一个，列之间要同时满足。勾选留在草稿里，点应用才进表。名称搜索另算 |
| 已选条件 | 找 | 每个已应用的值一枚，可以单独摘掉。清空只清筛选，名称搜索还在 |
| 列排序 | 看 | 点金额：不排 → 从高到低 → 从低到高 → 不排。只改顺序，条数不变 |
| 固定表头 | 看 | 表头 `sticky` 在表格滚动区顶部。横滑时名称列还在 |
| 自定义列 | 看 | 按这次任务开关字段。名称必选。选择框和操作不是字段 |
| 行操作 | 改 | 查看留在行上。编辑、复制、删除在这一行的更多里，删除在分隔线后 |
| 批量操作 | 改 | 已选数大于 0 才出现，写清条数，换掉搜索和列设置。全选只勾当前筛出来的行 |

筛完是 0 条时，记录还在，空白的原因是条件。翻页才会丢掉上一页。点金额换的是方向，不是把行拖成新顺序。

说清楚一层，用三件事：

1. **名称** — 表头筛选、列排序、固定表头、行操作、自定义列、批量操作、已选条件
2. **落点** — 找在列上和条件上，看在滚动区和字段上，改在这一行和已选数量上
3. **规则** — 草稿才应用、排序不改条数、名称不能关、批量条等数量

这三件事收成一句，就是卡片上的「说清楚」。

## 和「只摆字段」的差别

| | 只摆字段 | 按找 / 看 / 改分层 |
| --- | --- | --- |
| 筛选 | 表外一张表单，勾选立刻改表 | 从这一列打开，应用才进表 |
| 条件 | 上面不写，或者和搜索缠在一起 | 一值一枚，清空留下名称搜索 |
| 排序 | 条数变了，方向看不出 | 只重排，箭头标方向 |
| 表头 | 跟着整页滚走 | 钉在表自己的滚动区 |
| 字段 | 名称也能关 | 名称必选 |
| 一行 | 四个按钮铺开 | 露出查看，其余在更多 |
| 批量 | 没选中也占着工具条 | 有数量才换掉搜索；全选不勾被筛掉的行 |

## 机器

判断在无 DOM 的模块里：`rowMatches`、`visibleCustomers`、`cycleSort`、`chipsOf`、`columnOn`、`bulkVisible`、`selectionMark`、`actionPlace`、`missCause`、`reduceDesk`。

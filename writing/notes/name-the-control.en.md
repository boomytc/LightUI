title: Stop saying “make an input”
date: 2026-08-24
summary: A box you can type in is only the skin. Name fill versus pick first: one line or a paragraph, compared in view, a short list, type-to-find, or several at once.
related: control-taxonomy
---

“Make an input” describes a box you can type in. What people actually hit is whether this slot should be filled in, or picked from answers that already exist.

A brief is stuffed into one line, so it has nowhere to go. An email is drawn as a textarea, so a short value floats in a tall box. Three shipping options hide in a dropdown, so price and timing cannot be compared. Five cities force a search box first. Two hundred colleagues dump into one long list, so nobody can be found. Interest tags are radio dots, so the second pick wipes the first. “Agree to terms” is a radio group, so a boolean looks like rival tiers. They all look like inputs. They are not the same machine.

Ask three things first: the name, the scene, and whether this slot is filled in or picked from answers.

- **Text field**: fill it in; one line is enough.
- **Textarea**: fill it in; a paragraph.
- **Checkbox**: pick from answers; several at once.
- **Radio group**: few, must compare side by side; only one.
- **Select**: a short fixed list; closes on pick.
- **Combobox**: many; type to find, then pick.

The three pairs people mix up: a text field is not a textarea; visible radios are not a dropdown; searchable is not a short list. A single “agree to terms” is still a checkbox: it is one boolean, not rival tiers.

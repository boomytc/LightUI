# 进度

转圈只说了在等。真正要先定的是**进度能不能算**。

## 问题

「做个进度条」描述的是外观：一条在动的轨。真正会坏掉的是**把不能算的进度画成假百分比，或把能算的进度做成永远转圈**：

- 上传明明知道字节，却只给一个转圈
- 同步不知道还要多久，却从 1% 假走到 99% 卡住
- 分步任务被画成一条连续百分比，看不出卡在哪一步
- 聊天等待、语音识别被套上 0–100，用户会以为马上结束
- 骨架屏占着布局位子，被当成「工作正在发生」
- 完成结果被做成一条 toast，进度条一关就不知道成没成
- 阶段步骤被做成页签鱼骨：那是在选当前步，不是工作本身在往前走

用同一种转圈或假百分比去扛这些差异，不是让人空等，就是让人以为马上好了。

## 规则

先问进度能不能算，再选叶子。

**能算（确定进度）：** 显示 0–100，走到完成就停——不要循环假百分比。

| 叶子 | 用来干什么 | 规则 |
| --- | --- | --- |
| 平滑填充 | 上传 / 下载 | `transform: scaleX(p)`，origin 在左，不要改 `width` |
| 阶段步骤 | 任务分多步 | `done` / `active` / `todo` 节点，不是一条假条 |
| 环形百分比 | 强调完成度 | SVG `dashoffset`，从 12 点起笔，100% 停住 |
| 液体填充 | 体量感 / 大屏 | 液面 `translateY`，可带波浪，涨满停住 |

**不能算（不确定进度）：** 不显示百分比，循环「还在干活」。

| 叶子 | 用来干什么 | 规则 |
| --- | --- | --- |
| 循环同步 | 时长未知的刷新 | 开口弧旋转，不要走向 100% |
| 雷达扫描 | 搜索 / 探测 | conic 扇区扫描，不是普通转圈 |
| 三点跳动 | 聊天短时等待 | 三点错开跳动，不要轨道 |
| 音频波纹 | 语音识别 | 竖条 `scaleY`，不要静态音量图标 |
| 按钮锁定 | 提交 / 生成 | 铬长在触发器上；`disabled` + `aria-busy`；**不要百分比** |

最容易混的几对：

- **进度不是骨架。** 进度是工作正在发生。骨架占的是布局位子，内容还没到。
- **进度不是 toast。** toast 说的是结果已经出来。进度说的是还在做。
- **阶段步骤不是页签鱼骨。** 鱼骨是导航的选中模型，点哪一步就看哪一步。这里的节点就是工作本身：完成的打勾，当前的在做，后面的还没开始。
- **不确定进度不要画假百分比。** 转圈、雷达、跳动、波纹、按钮锁定只保证「还在」，不保证「还剩多少」。
- **按钮锁定不是面状重量。** 重量是这一击有多重。这里锁的是触发它的那一粒铬。

说清楚一条进度，用三件事：

1. **能不能算** — 能算就走到 100 停住；不能算就循环
2. **场景** — 上传、分步解析、仪表盘、同步、扫描、聊天、语音
3. **规则** — scaleX、三态节点、dashoffset、液面、开口弧、雷达扇区、三点、波纹

## 和「一律转圈 / 假百分比」的差别

| | 一律转圈或假 % | 先问能不能算 |
| --- | --- | --- |
| 上传 / 下载 | 转圈，或 1% 假走到 99% | scaleX 真百分比，走完停住 |
| 分步解析 | 一条连续条，看不出卡在哪 | 三态节点，当前步在动 |
| 仪表盘完成度 | 圆环一直转 | dashoffset 走到 100 停 |
| 容量大屏 | 细环或假涨 | 液面涨到满停住 |
| 同步 / 扫描 | 假百分比卡在 99% | 开口弧或雷达一直转，没有数字 |
| 聊天等待 | 一条小进度条 | 三点跳动 |
| 语音识别 | 静态喇叭图标 | 波形在起伏 |

## 机器

分类和几何在无 DOM 的模块里：`category`、`clampProgress`（0..1）、`showPercent`（仅确定进度）、`stepKind`（done / active / todo，active 就是当前）、`circularOffset = C * (1-p)`、`shouldLoop`、`prefersStatic`。填充只用 scaleX，不要测 width。

`prefers-reduced-motion` 时：确定进度可以停在当前 p，或一下跳到完成；不确定进度变成静止标记，不要再循环。

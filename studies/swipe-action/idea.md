# 列表侧滑

列表行向左侧滑时，手势如何区分横竖意图，并在操作露出与全滑提交之间裁定？先定**手势死区与锁轴消歧机制，以及双阈值（吸附露出 vs 越界直接提交）的状态裁定模型**。

## 问题

「做个左滑删除」只描述了最终视觉效果。真正会坏掉的是**多手势冲突与操作意图裁定的粗暴割裂**：

- **横竖手势打架，列表卡顿吞滚动**：用户手指本来是在顺畅地向下滚屏浏览，手指轻微斜移了 3px，系统误识别为侧滑并劫持手势，导致滚屏骤停；或者想向左侧滑时被垂直滚动抢走，行卡在半路发抖；
- **每一行常驻红色删除按钮**：在窄屏列表每一行末尾死死钉着垃圾桶图标，挤占标题与正文空间，且单手握持极易误触误删；
- **缺乏深滑直接提交，多做一次机械点击**：用户左滑展开了「删除」按钮，手指已经向左拉了极大幅度（表达了极其明确的删除诉求），却必须把手指挪回按钮上再点一击，连贯的手势被打断；
- **多行同时展开成斑马线**：滑开第 1 行后，再去滑第 2 行，第 1 行依然大敞着，整个列表千疮百孔，没有自动收回互斥。

用同一种「无容差滑动」或「常驻按钮」去扛列表快捷操作，不是误触频发，就是交互体验极其生硬。

## 规则

移动端列表侧滑遵循**死区矢量消歧 + 阻尼越界 + 双阈值裁定（吸附露出 vs 全滑提交）+ 单行排他**模型。

| 阶段 | 物理与几何规则 | 体验与系统行为 |
| --- | --- | --- |
| **8px 矢量消歧与锁轴** | $\sqrt{\Delta x^2 + \Delta y^2} < 8\text{px}$ 保持待定；若 $|\Delta y| > |\Delta x|$ 判为纵向浏览，立即放行原生滚动；若 $|\Delta x| \ge |\Delta y|$ 判为侧滑，捕获指针并阻止垂直滚动 | 绝不吞掉正常的滑屏浏览，告别手抖误触发 |
| **双阈值释放裁定** | ① 位移 $< 45\%\times 148\text{px}$：弹性回弹归零<br>② $45\% \le \text{位移} < 172\text{px}$：吸附露出「标记已读」与「删除」<br>③ $\text{位移} \ge 172\text{px}$：整行变红，松手一步全滑直接删除 | 轻拉看动作，深拉直接走，操作效率拉满 |
| **单行互斥排他性** | 当触摸或滑动任何一行时，此前处于展开态的其他行立即平滑回弹复位 | 保证界面永远只有最多一个操作面板敞开，视觉整洁 |
| **点外快速复位** | 点击已展开行的内容区或列表空白区，立即闭合展开的操作面板 | 极其低廉的后悔通道，无需精准点取消 |

最容易混的几对：

- **列表侧滑不是危险操作确认滑块。** 二次确认阶梯（`confirm-taxonomy`）中的滑动只是作为高危操作的物理拦截门槛；列表侧滑是一整套集成了消歧、露出、单行互斥与全滑提交的快捷手势体系。
- **列表侧滑不是长按多选。** 侧滑针对当前单条记录做行内快捷处理；长按选择（`press-select`）是将整个列表切换至批量选择多选模式。
- **列表侧滑不是下拉刷新。** 下拉刷新（`pull-refresh`）是顶边容器级的纵向接管；侧滑是列表内部单个行容器的局部横向接管。
- **列表侧滑不是拖放重排。** 拖拽提交（`drag-commit`）改的是数据记录在列表里的前后物理排序。

说清楚一次列表侧滑，用三件事（交互公式）：

1. **名称** — 列表侧滑操作（Swipe Action / Swipe to Reveal & Commit）
2. **触发手势** — 向左滑动 / 持续深滑
3. **展开结果** — 露出快捷操作，全滑直接删除

## 和「常驻按钮 / 无消歧侧滑」的差别

| | 常驻删除图标 | 无消歧直接侧滑 | 8px 消歧 + 双阈值侧滑 |
| --- | --- | --- | --- |
| 版面空间 | 挤占 48px 内容展示区 | 全宽展示 | **全宽展示，内容利用率 100%** |
| 误触率 | 高（手指边缘容易误碰） | 极高（竖向滑屏容易卡住） | **极低（8px 矢量判轴，竖屏优先）** |
| 操作步数 | 1 步但易误删 | 2 步（滑开再点删除） | **轻滑 2 步，深滑 1 步，灵活自如** |
| 多项管理 | 互相独立 | 容易同时露出多行 | **单行排他互斥，点外瞬时收回** |

## 机器

状态机在无 DOM 的纯算法模块里：`resolveGestureLock`（8px 欧氏位移方向锁轴）、`calcDragOffset`（带阻尼的左右边界位移计算）、`resolveSwipeRelease`（双阈值释放裁定：`commit` / `reveal` / `close`）、`calcActionProgress`。

# 滚动条

滚动提示是开场邀请，还是位置轨道？先定**这一根条报什么**，再谈皮肤。

## 问题

「做个酷滚动条」描述的是外观：藏掉系统拇指，右边画点、画箭头。真正会坏掉的是**职责对不上**：

- 还停在顶上，却画一列位置点，人不知道下面还有
- 已经在滚，箭头还在晃，轨道和邀请抢同一根条
- 点列看起来像目录，点一下却跳到滚动比例，不是标题
- 把文档滚过画成工作 0–100
- 没有溢出还留着装饰
- 藏掉系统条，自定义铬又 `aria-hidden`，键盘没有可抓的控件
- 轨道跟了整窗，侧栏里的长文稿滚的是另一格

用同一次变形去扛这些差异，不是让人找不到现在在哪，就是让人以为点的是章节。

## 规则

先问还在顶上、还是已经在滚。再选叶子。

| 叶子 | 何时 | 机器 |
| --- | --- | --- |
| 系统条 | 溢出归操作系统 | `hidesNative` 为假；拇指连续可拖 |
| 邀请 | 有溢出，且还停在顶上 | `showsCue`；点一下 `current + viewport`；离开顶上卸掉 |
| 轨道 | 有溢出 | `showsTrack`；`focus = round(fraction × (n − 1))`；点中 `i / (n − 1) × max` |

轨道绑在**这一格视口**上，不要绑 `window`。`overflow` 不够就 `hidden`。

点列量化的是滚动比例，不是标题。降动效时箭头不晃，伸长一次到位，跳转不要平滑。

不要把邀请和轨道缝成一次变形。那是两种任务。

最容易混的几对：

- **文档比例不是工作进度。** 进度问能不能数到 100。这里问溢出报什么。
- **点列不是章节锚点。** 高亮当前标题是导航。
- **邀请不是轨道。** 顶上才请人往下；滚起来才报位置。

说清楚一根滚动条，用三件事：

1. **名称** — 不要说「做个酷滚动条」，说系统条、邀请或轨道
2. **场景** — 还在顶上还是已经在滚；有没有溢出
3. **规则** — 藏不藏系统条；邀请只在顶上；轨道点的是比例

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一律画更酷的条」的差别

| | 一律变形装饰 | 按职责分 |
| --- | --- | --- |
| 顶上 | 已经是点列 | 邀请：下面还有 |
| 滚起来 | 箭头还在，或点和箭头抢 | 轨道：现在在哪 |
| 短文稿 | 装饰还在 | hidden |
| 点一下 | 说不清跳到哪 | 一屏，或 i/(n−1) |

## 机器

判断在无 DOM 的模块里：`hidesNative`、`showsCue`、`showsTrack`、`focusDot`、`seekTop`。舞台 `state=start|mid|end|fit` 锁住滚动比例；`fit` 是没有溢出。

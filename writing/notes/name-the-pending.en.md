title: Stop saying “make a loading state”
date: 2026-08-24
summary: A spinner and a blank board are only the skin. Name the placeholder first: a skeleton that holds layout, or an empty state that offers a next step.

“Make a loading state” describes a spinner, gray blocks, or a blank board. What people actually hit is a placeholder that does not match the content.

The list is still arriving, so a spinner sits in the middle and the page jumps when it lands. The shimmer flashes opacity, which reads as an alarm. Arrival is a hard cut, so cards pop in. The list is empty, but the copy says “no data”, or the board is blank. The empty state is a toast: a glance, then gone. They all look like loading. They are not the same machine.

Ask three things first: the name, the scene, and whether it holds layout or offers a next step.

- **Skeleton**: holds the layout. Blocks match the final size; shimmer runs on the background; a short crossfade on arrival. Not a spinner.
- **Empty state**: offers a next step. A human title plus one primary button. Not “no data”.

The pairs people mix up: a skeleton is not a spinner; an empty state is not a notice.

A spinner is progress that cannot be counted yet, in [Progress](/s/progress-taxonomy). An empty state is not a notice, in [Notice](/s/notify-taxonomy). How the questions chain is on the [map](/graph).

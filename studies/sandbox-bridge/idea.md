# 沙盒桥：字段按顺序到来，高度只信报告，回传先过白名单

生成式界面若让模型直接改宿主页面，一段没写完的样式、一次伪造的点击、一个无限高的数字，都会落到用户正在看的文档上。用 iframe 把生成结果隔开之后，宿主和沙盒之间只剩一条消息桥。桥若只是「收到什么画什么」，隔离就只是样子。

## 缺失时用户会遭遇什么

1. **光秃秃的结构先于样式出现。** HTML 比 CSS 先到一截时，用户会看到未排版的按钮和文字，再被随后的样式猛地重排。
2. **高度被沙盒单方面决定。** 沙盒报一个 `Infinity` 或几万像素，宿主页面被撑开，把后面的内容推出视口。
3. **回传等于任意调用。** 沙盒里的脚本只要能 `postMessage`，就能让宿主代为打开链接、提交提示词，或摸到不该摸的函数。包装一层 `sandboxHost` 挡不住自己组消息的脚本。

## 规则

流按这个顺序长大：`initialHeight`、`placeholderMessages`、`css`、`html`、`jsFunctions`、`jsExpressions`。`html` 与 `jsExpressions` 是字符串数组，其余文本字段是单个字符串。每个字段在自己的 JSON 值结束时记一笔 `*Complete`。整段还在长时 `generating` 为真，源文本结束时为假。

宿主的可见阶段只看完成标志，不看「后面的键是否已经出现在缓冲区里」：

| 阶段 | 条件 | 用户看到的 |
| --- | --- | --- |
| 占位 | `css` 尚未完成 | 已到达的占位句，框高用 `initialHeight`（还没有则用 200） |
| 预览 | `css` 已完成，`html` 未完成 | 把已经到达的 HTML 片段拼进沙盒，不跑脚本 |
| 运行 | `html` 已完成 | 文档固定下来；`jsFunctions` 完成后注入一次；只跑已经闭合的表达式 |

高度不是宿主去量沙盒 DOM。沙盒用 `ResizeObserver` 量自己的内容盒，再报一个数字。宿主先确认 `event.source` 是当前这只 iframe 的 `contentWindow`，再要求数字有限，并钳到 50–4000。`sandbox` 只有 `allow-scripts`，没有 `allow-same-origin`，因此 `event.origin` 是 `"null"`，不能拿来当同一来源的证据。

沙盒到宿主的调用只有两个：

- `sendPrompt({ text })`：`text` 是字符串，去掉首尾空白后长度 1–4000，对象上不能有别的键。
- `openLink({ url })`：`url` 必须能解析，且协议是 `https:`。

名字不在这张表上，或参数对不上，宿主拒绝，并且不产生「已收下」的副作用。白名单做在宿主对消息的校验上，不依赖沙盒里那个礼貌的包装函数。

## 为什么朴素做法更糟

| 做法 | 问题 |
| --- | --- |
| 缓冲区里有 HTML 就先画 | 样式未完成时用户看到的是半截结构，随后整块跳动。 |
| 把 iframe 高度设成 `100%` 或直接信 `scrollHeight` | 视口高度和内容高度缠在一起，沙盒变矮时宿主不会跟着缩。 |
| `sandbox` 加上 `allow-same-origin` | srcdoc 与宿主同源，沙盒能读到宿主的存储和 DOM，隔离消失。 |
| 只在沙盒里隐藏危险函数 | 脚本仍可直接 `postMessage`。拒绝必须发生在宿主。 |

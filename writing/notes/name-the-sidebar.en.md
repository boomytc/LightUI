---
title: Stop saying “make a sidebar”
date: 2026-08-15
summary: Flush-left is only the skin. Name the space model first: occupy or overlay, grow or slide, a tree or a selector.
related: sidebar-taxonomy
---

“Make a sidebar” describes a nav rail on the left. What people actually hit is how space is given back to the main view.

A portfolio lights every item, because that list is a selector, not a tree. Analytics forever occupies 240px and the table is cramped. A long-form TOC crowds the essay, then disappears on a small screen. A dense admin never ends, and a parent is treated as a page. They all look like sidebars. They are not the same machine.

Ask three things first: the name, the scene, and whether expand changes width or layer.

- **Island**: occupies, inset from the edge.
- **Wheel**: commits only on the baseline.
- **Multi-level**: a parent files the list.
- **Collapse**: changes width; the main view grows; shut still occupies an icon rail.
- **Off-canvas**: zero width until it slides in.

The pairs people mix up: collapse is not off-canvas; multi-level is not a wheel.

# 层递

看板该从结果往下钻。一盘端上 KPI、图、表，扫得到皮，钻不到因。

## 问题

「做个看板」描述的是外观：有数、有卡、有图。真正会坏掉的是**信息层级被摊平**：

- 一打开 KPI、趋势、明细全在场，不知道先看什么
- 点一张卡只是换图种，粒度没变
- KPI + 图 + 表的仪表盘皮，被当成已经讲完结构
- 表铺满一页，变化最大的那一行被埋住
- 三层叠着往下滚，看起来像层递，其实还是一盘端上来

用「多放几张图」去扛这些问题，不是拼盘，就是一张扫数字的皮。

## 规则

先定这块板是从结果往下钻，还是一盘端上来。点一个结果，才展开下一层。不要一上来铺满所有表。

| 叶子 | 何时 | 机器 |
| --- | --- | --- |
| 层递 | 要从结果找到原因 | `canExpand`；`layerOf` 走 kpi → dim → detail |
| 一盘端 | 只要扫一眼，不钻 | `showsAll`；KPI、小趋势、表同时在场 |

最容易混的两对：

- **下钻不是换图种。** 图种回答这组数据要看什么。下钻换的是粒度：同一指标，从 KPI 到维度到明细。
- **层递不是仪表盘皮。** KPI + 图 + 表是一页怎么铺。是不是点了才展开下一层，是另一问。

说清楚一块看板，用三件事：

1. **名称** — 不要说「做个看板」，说层递或一盘端
2. **场景** — 从结果往下钻，还是扫一眼
3. **规则** — 点一个结果才展开下一层；一盘端不钻

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一盘端上来」的差别

| | 一盘端 | 层递 |
| --- | --- | --- |
| 打开 | KPI、图、表同时在场 | 只见结果 |
| 点 KPI | 高亮，或不做事 | 展开维度表 |
| 点一行 | 还是整张表 | 展开短明细 |
| 找主因 | 自己扫 | 顺着点进去 |

## 机器

判断在无 DOM 的模块里：`layerOf(view, selection)`（kpi / dim / detail）、`showsAll(view)`（一盘端为真）、`canExpand(view)`（层递为真）。

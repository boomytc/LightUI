# 助手

助手不是默认整页聊天。真正要先定的是**它住在哪**：对话、侧栏、插件、浮层、画布，还是看不见。

## 问题

「做个 AI 产品」描述的是外观：加一个对话框。真正会坏掉的是**助手占的位置和任务对不上**：

- 已经有编辑器了，还把整页换成聊天，干活的地方没了
- 选区就是上下文，却在侧栏再开一轮对话流
- 老产品只想加能力，却改了排版、加了侧栏
- 正在读的文档，被推进另一个全屏应用
- 点子要摊开，却被收进时间线气泡
- 分类、归档这种不需要讨论的任务，硬加一块铬

用同一种聊天窗去扛这些差异，不是宿主被掀掉，就是工具条长成弹窗，就是看不见的活被做成常驻助手。

## 规则

先问助手住哪，再谈皮肤。这不是整页怎么铺，也不是弹窗打不打断。

| 叶子 | 住哪 | 机器 |
| --- | --- | --- |
| 对话式 | 整页消息列表 | `occupiesPage`；Enter 发送必须避开 IME 组字 |
| 面板分割 | 左干活右建议卡 | `needsSelection`；选区即上下文；应用 / 撤销 |
| 插件式 | 宿主不动，选中才出工具条 | `needsSelection`；保存 Range |
| 浮层助手 | 可拖的小窗，不改骨架 | 页面照常读；球可拖 |
| 画布 | 无限画布上的节点 | `occupiesPage`；输出是节点，不是聊天窗 |
| 看不见 | 快捷键触发，没有常驻铬 | `chromeVisible` 为假 |

最容易混的几对：

- **助手住哪不是整页骨架。** 骨架回答这一页怎么铺。助手住对话、侧栏、插件、浮层、画布，还是看不见，是另一问。
- **选区工具条不是弹窗。** 插件式贴着选区冒出来，宿主页面不动。弹窗才谈打不打断、贴不贴触发点。
- **可拖小窗不是必须先处理的弹窗。** 浮层助手不改骨架，页面仍可读。弹窗要先处理完才能继续。
- **侧栏建议卡不是对话流。** 面板是一段话 + 应用 / 撤销。整页消息列表才是对话。

说清楚一处助手，用三件事：

1. **名称** — 不要说「做个聊天」
2. **场景** — 想法还散着、对着选区改、老产品加能力、跨页问一句、点子摊开，还是后台写回
3. **规则** — 占不占整页、要不要选区、铬看不看得见、组字中的回车发不发

这三件事收成一句，就是卡片上的「说清楚」。

## 和「一律做成聊天窗」的差别

| | 一律聊天窗 | 按住处分 |
| --- | --- | --- |
| 还没想清楚 | 合适 | 整页消息列表；组字中的 Enter 不上屏就提交 |
| 写代码、改文档 | 选区丢了，建议变成闲聊 | 左干活，右一张建议卡；能应用、能撤销 |
| 老产品 | 改排版、加侧栏 | 选中才出工具条；保存 Range |
| 正在读的文档 | 跳进另一个应用 | 可拖的小窗，骨架不动 |
| 头脑风暴 | 时间线气泡 | 画布上的节点和连线 |
| 相册分类 | 多一块铬 | 快捷键；结果写回原处 |

## 机器

判断在无 DOM 的模块里：`occupiesPage(kind)`（对话、画布为真）、`needsSelection(kind)`（插件、面板为真）、`chromeVisible(kind)`（看不见为假）、`shouldSendOnEnter(composing)`（组字中为假；`keyCode` 229 同样不发）。

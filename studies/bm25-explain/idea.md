# 检索可解释性

检索排序不是黑盒总分。先定稀疏与向量的分数不可直接相加，再把得分拆解为词频饱和与篇幅惩罚。

## 问题

现代全文检索与 RAG 架构普遍把检索结果当作「黑盒打分」：

- 把稀疏检索（BM25）的绝对分与稠密向量的余弦相似度直接相加，量级失衡却找不出 Bad Case 出在哪
- 以为词频（TF）越高越好，结果长篇大论凭借刷词挤掉短而精的精准命中
- 以为所有命中的词都一样重，忽略了高频泛词（如「方法论」「评估」）与核心实体词（如「Q3」「营收」）在 IDF 上的巨大鸿沟
- 面对排序异常，不知道是分词切散了、停用词没滤掉、篇幅被惩罚了，还是参数 $k_1$ / $b$ 设置不当

把检索只当成「调一个 `search()` 接口」，遇到排序错误就只能盲目调 prompt 或重训向量模型。

## 规则

把检索排序拆成三层认知，建立可检验的可视化通道：

1. **分水量级与多路融合**
   - 稀疏（BM25）是基于逆文档频率与词频的无界非负分；向量检索是 [-1, 1] 的余弦相似度。
   - 两路不能直接加和，必须走 **RRF（倒数排名融合 $\frac{1}{k + rank}$）** 或 **按最大值归一（Max-norm）加权**。
2. **Lucene BM25 的三维拆解**
   - **IDF 稀缺度**：$\ln(1 + \frac{N - df + 0.5}{df + 0.5})$，出现越少的词越值钱。Lucene 相比 Robertson 原版加了常数 1，保证恒为正。
   - **词频饱和（$k_1$）**：控制词频增益上限为 $k_1 + 1$ 倍。默认 1.2，防止刷词无限膨胀。
   - **篇幅惩罚（$b$）**：按 $|D| / avgdl$ 衡量文档相对长度。默认 0.75，篇幅短而命中完整的文档享有天然提权。
3. **流水线逐级透明化**
   - Query → Tokenize 分词 → Inverted Index 倒排定位 → BM25 公式拆解 → 贡献瀑布图 → 调参响应。

## 和「黑盒打分」的差别

| | 黑盒打分 | 检索可解释性 |
| --- | --- | --- |
| 坏案例排查 | 盲猜模型不好 | 逐词查看 IDF、TF 饱和度与篇幅惩罚项 |
| 多路融合 | 暴力加权导致量级吞没 | RRF 位次融合或归一化加权 |
| 调参依据 | 随机试参 | 动态观察 $k_1$（饱和斜率）与 $b$（长度斜率）对曲线的影响 |
| 分词影响 | 不清楚为何漏召回 | 直观对照整词、中文子词与 Porter 英文词干提取 |

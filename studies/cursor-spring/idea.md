# 协作光标：稀疏网络采样的弹簧物理重建

多人实时协作应用（如 Figma、Miro、Linear、Liveblocks、协作画布与在线文档）中，屏幕上同时穿梭着多位协作者的光标。网络带宽与延迟限制决定了远程光标坐标不可能以 60–120 Hz 全量实时广播，通常只能以 8–20 Hz 甚至更低的离散采样包传输。

光标如果直接按包瞬移，动作会严重卡顿顿挫；如果单纯使用线性插值，又会丢失惯性、转角拖泥带水；如果使用 CSS 过渡，中途到达的新包会打断并引发跳帧。如何用极简的物理系统，在客户端将稀疏离散的采样包平滑重建为具有自然惯性与微过冲的连续光标？

## 缺了会发生什么

若缺少连续平滑重建，多人协作的临场感与空间指引体验将大幅受损：

1. **瞬移卡顿（Stuttering Teleportation）**：10–16 Hz 的网络包使远程光标在画布上跳跃位移，眼睛难以建立连续的视线轨迹追踪，误以为网络严重卡死。
2. **转向迟滞（Viscous Drag）**：线性插值（lerp）在高速转向时无法传递手部肌肉自然产生的速度冲量，光标像粘在厚泥浆里，慢半拍且无微过冲。
3. **连续打断颠簸（Jittery Retargeting）**：使用 CSS transition `left/top` 时，一旦新数据包在过渡中途到达，浏览器强制重置起始点，造成肉眼可见的瞬移抖动。

## 真正的规则

采用**二阶弹簧-质量-阻尼系统（Spring-Mass-Damper）**，在客户端 `requestAnimationFrame`（rAF）渲染循环中进行**半隐式欧拉积分（Semi-implicit Euler Integration）**，将网络包的到达频率与本地屏幕高刷彻底解耦。

### 1. 动力学控制方程

将远程光标抽象为一个受虚拟弹簧拉动的质点：

$$a = \frac{-k \cdot (x - x_{\text{target}}) - c \cdot v}{m}$$

$$v \leftarrow v + a \cdot \Delta t$$

$$x \leftarrow x + v \cdot \Delta t$$

- **刚度 $k$（Stiffness）**：弹簧拉力系数。$k$ 越大，光标追赶目标点的加速度越大。
- **阻尼 $c$（Damping）**：阻力系数。消耗系统的动能，控制振荡与衰减速度。
- **质量 $m$（Mass）**：光标虚拟惯性质量。$m$ 越大，启动与制动所需的力越大，轨迹越柔和。

### 2. 临界阻尼与阻尼比

系统的运动形态由无量纲**阻尼比 $\zeta$（Damping Ratio）** 决定：

$$\zeta = \frac{c}{2\sqrt{k \cdot m}}$$

- **欠阻尼（$\zeta < 1$）**：转弯时有轻微惯性冲出轨道，形成柔和的微过冲（Overshoot），与真实手部运动极其神似（默认预设推荐 $\zeta \approx 0.65$）。
- **临界阻尼（$\zeta \approx 1$）**：以最快速度贴合目标点且绝不过冲，适合要求精准无晃动的操作。
- **过阻尼（$\zeta > 1$）**：能量衰减过快，光标移动沉重迟缓。

### 3. 工程稳定三法则

1. **变步长子步切分（Substepping）**：为防止浏览器切后台或帧率波动时过大的 $\Delta t$ 导致积分发散（飞出屏幕），将每帧步长硬限制在 $\Delta t \le 48\text{ms}$，并按 $8\text{ms}$ 划分微子步逐级迭代。
2. **微位移死区吸附（Deadband Settle）**：在归一化空间中，当光标与目标点距离平方 $< 10^{-6}$（约 $< 0.8\text{px}$ 亚像素死区）且速度平方 $< 10^{-4}$ 时，强制将位置吸附至目标点并将速度清零，消除低速浮点微颤。
3. **DOM 变换脱离 React 重绘（Transform Push）**：位置更新直接通过 `element.style.transform = translate3d(...)` 推送 GPU 硬件加速图层，严禁在 60/120fps 的 rAF 中调用 React `setState`。

## 为什么不选朴素替代

| 方案 | 机制 | 缺陷 |
| --- | --- | --- |
| **原生瞬移** | 每收到一包直接改坐标 | 10–20Hz 离散点跳跃，视线脱节，顿挫感严重 |
| **线性插值 (Lerp)** | $x \leftarrow x + (x_{\text{target}} - x) \cdot \lambda$ | 无加速度与速度状态，永远无过冲，转急弯时迟滞发黏 |
| **CSS 过渡** | `transition: transform 100ms` | 无法优雅处理提前到达的新数据包，重定向导致跳跃抖动 |
| **样条曲线拟合** | 收集多个历史点拟合 Hermite/Catmull-Rom | 必须累积 2–3 个点才能计算切线，引入不可接受的 100–200ms 强制显示延迟 |
| **弹簧物理积分 (本项目)** | 二阶半隐式欧拉积分 + 8ms 子步 | 零附加缓冲延迟，动态吸收网络抖动，自然微过冲还原真实手部惯性 |

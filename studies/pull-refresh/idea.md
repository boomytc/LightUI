# 下拉刷新

下拉手势何时接管滚动、何时提交刷新？先定**顶边阻尼接管与临界阈值提交**，还是**显式刷新按钮**。

## 问题

「下拉刷新」只说了能往下拉。真正会坏掉的是**手势接管时机、阻尼物理手感与回弹时序**：

- 列表滚动在半腰时，向下拉动意外触发了刷新，打断用户正常的向上回滚浏览
- 没有物理阻尼，下拉距离和手指位移 1:1 硬拉，缺乏弹簧般的受力反馈
- 松手时没有阈值判断：只要拉动了 2px 就开火请求，导致大量误触发
- 刷新完成后没有状态展示或时间戳提示，界面突然跳回，用户不知道是否拿到了新数据
- 在桌面端鼠标环境下硬搬下拉刷新，既别扭又浪费空间

用同一种「硬拉开火」或「无条件拦截」去扛这些差异，不是频繁误触卡死，就是手感僵硬缺乏呼吸感。

## 规则

先问交互时机与手势状态，再定阻尼与提交曲线。

| 阶段 | 触发条件 | 视觉与物理表现 |
| --- | --- | --- |
| 常规滚动 | `scrollTop > 0` | 原生列表滚动，手势不拦截 |
| 阻尼下拉 | `scrollTop === 0` 且 `dy > 0` | 接管手势，位移按 $y = \min(y_{\max}, dy \times 0.42)$ 阻尼延伸，指示器随位移自旋 |
| 临界达标 | $y \ge \text{threshold}$ (56px) | 提示松手即可刷新，指示器进入高亮激活态 |
| 提交刷新 | 超过阈值后松手 (`pointerup`) | 弹性回弹至 56px 悬停（Pin），指示器循环旋转，触发数据请求 |
| 未达回弹 | 未达阈值松手 (`pointerup`) | 无感弹性复位至 0px，不发起请求 |
| 完成收起 | 数据就绪 | 顶部滑出更新提示横条（如「已拉取 3 条最新资讯」），延迟后平滑收回至 0px |

最容易混的几对：

- **下拉刷新不是滚动条轨道。** 滚动条是反映当前视口在全长文档中的比例；下拉刷新是边界溢出触发的事件发生器。
- **顶部下拉刷新不是底部追加记录。** 下拉刷新作用于列表顶端获取最新前缀；底部追加作用于末尾延长可视范围。
- **下拉阻尼指示器不是工作进度条。** 指示器反映的是当前下拉手势的拉力与完成度，松手后进入确定刷新态。

说清楚一次下拉刷新，用三件事：

1. **名称** — 不要说「下拉加载」，说顶部阻尼接管与阈值提交
2. **场景** — 移动端新闻资讯、社交动态、任务列表
3. **规则** — 顶边判决、0.42 阻尼系数、56px 临界阈值、吸顶反馈与回弹物理

## 和「无阻尼硬拉 / 误触开火」的差别

| | 无阻尼硬拉 | 误触开火 | 阻尼阈值下拉刷新 |
| --- | --- | --- | --- |
| 接管时机 | 全程拦截 | 任意滚动位置 | 仅在 `scrollTop <= 0` 时接管 |
| 手指手感 | 僵硬线性，缺乏弹性 | 无手感 | 0.42 阻尼随拉动距离增加阻力 |
| 松手决策 | 必定触发请求 | 必定触发 | 超过 56px 才提交，否则平滑归零 |

## 机器

判断在无 DOM 的模块里：`calculatePull(dy, damping, max)`、`shouldTakeoverScroll(scrollTop, dy)`、`isThresholdMet(pull, threshold)`、`pullProgress(pull, threshold)`。
